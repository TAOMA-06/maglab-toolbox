## 2. 技术设计（对齐 internal/ 三层架构锁）

### 2.1 parse 扩展（只提事实，不做归因）

demoinfocs-golang v5.2.0 API 已核实（`common/player.go`）：`ViewDirectionX/Y()`（yaw/pitch）、`Position()`、`PositionEyes()`。

| 新增事实 | 来源 | 备注 |
| --- | --- | --- |
| 视角朝向时间线（yaw/pitch） | `Player.ViewDirectionX/Y()` | 以事件对齐采样（不需要每 tick 全量） |
| 开枪瞬间移动速度 | `Position()` 差分 | 急停判定用 |
| 接敌事件对（双方位置 + 双方朝向） | 击杀/受伤事件 + 位置 + 视角 | "接敌瞬间" = 首次开火前 1s 窗口快照 |

数据契约变更集中在 `internal/model`（`Match` 增 duel / positioning 事实字段），`docs/CONTRACTS.md` 同步冻结。架构锁不变：这层只写事实字段。

后续扩展（T2 前，胜率模型要）：双方存活血量时间线 `hp_ct/hp_t/hp_diff`（cs2-wpa 对比结论：残局血量是实在信息缺口；事件级伤害已有，缺的是每 tick 双方血量和）。与 M2b 收口一起做，不单独排期。

### 2.2 tactics-A 站位（规则，零 LLM）

| 指标 | 计算 | 输出 |
| --- | --- | --- |
| 死亡热区 | 死亡位置半径聚类 | 每玩家 top3 危险坐标 |
| 暴露枪线数 | 死亡瞬间能看到你的存活敌人数量 + 方位扇区 | 每次死亡暴露 1..n，带敌人方位 |
| 队友间距 | 死亡瞬间与最近队友距离 | trade 可能性近似 |
| 道具掩护缺失 | 死亡前 10s 内是否有烟/火/闪覆盖你所在扇区 | bool + tick 证据 |

高危站位判定必须是量化规则（如：暴露枪线 ≥2 且无掩护道具），禁止主观形容词输出。

### 2.3 tactics-B 对枪（规则，零 LLM）

| 指标 | 计算 | 输出 |
| --- | --- | --- |
| 预瞄角度差 | 接敌瞬间准星朝向 vs 敌人方位角 | 度数；超阈值 = 预瞄失败（阈值见 2.5） |
| 急停质量 | 开枪瞬间水平速度 | u/s；超阈值 = 移动中开枪 |
| 先手/命中归因 | 首发时间差、对枪命中率 | 对枪胜负归因类别 |

### 2.4 coach（只解读不发明）

报告新增「站位」「对枪」两节；每条结论过 `ValidateCitations` 证据校验（回合号 + tick）；无 LLM 降级时纯事实版同样含两节。

### 2.5 阈值纪律

预瞄角度差 / 急停速度的"坏"阈值不许拍脑袋：M2b 先输出用户自己 3 场 demo 的指标分布，据分布定阈值；阈值为具名常量集中 `internal/tactics`，可调。

## 3. 验收（同一次交付，两个独立检查点）

| 检查点 | 标准 | 失败处置 |
| --- | --- | --- |
| M2a 数据抽查 | 3 场 demo 新字段（视角/速度/接敌）人工抽查 5 次对枪，与回放一致 | 对不上 → 只返工 parse；2 轮不过 → 降级砍对枪保站位 |
| CP-A 站位 | ≥3 场报告各指出 ≥3 个高危站位（带 tick 证据），用户判"至少 1 条下把能用" | 连续 3 场全"正确的废话" → 只砍站位模块 |
| CP-B 对枪 | ≥3 场报告各含 ≥5 次对枪的预瞄/急停指标（带 tick 证据），用户判"至少 1 条下把能用" | 同上 → 只砍对枪模块 |
