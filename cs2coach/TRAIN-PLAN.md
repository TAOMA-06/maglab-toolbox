- 日期: 2026-11-01
- 状态: v2 已确认（用户拍板：预测模型为主线，DPO 降为可选支线）；T0/T1 执行文件已落地 `learn/`
- 取代 v1（偏好对齐主线，2026-11-01 当日废弃）；决策记录见 work-kb `projects/cs2-demo-review/decisions.md`

## 0. 一句话

训练一个**胜率/价值模型**作为游戏理解的载体：输入 tick 级局面 → 输出回合胜率。理解 = 可验证的预测能力，不是说话风格；LLM 只把模型的数字讲成人话。

## 1. 路线决策（2026-11-01 v2）

| 项 | v1（已废弃） | v2 | 理由 |
| --- | --- | --- | --- |
| 主线 | DPO 调 LLM 说话 | **胜率/价值模型（预测式理解）** | 用户要"理解游戏"不是"猜游戏说话"；预测能力是唯一可验收的"理解"定义 |
| LLM 角色 | 被训练对象 | 讲解员（不训练，或仅可选微调） | 理解在预测模型里，不在话术里 |
| 训练信号 | 👍/👎 偏好对 | **回合胜负**（demo 现成、自动、量大） | 不靠人工攒数据 |
| 训练类型 | DPO（偏好优化） | **监督学习**（标签=回合胜负） | RL/反事实/世界模型仍是死路，不变 |
| DPO 线 | 主体 | 可选支线（仅调讲解风格） | schema 见附录 |
| self-play RL | ❌ | ❌ 不变 | CS2 无 macOS 版 + 算力硬墙（2026-11-01 查证） |

## 2. "理解"的验收定义（先定义，再训练）

| 指标 | 标准 |
| --- | --- |
| 主指标 | 回合胜率预测显著优于基线（AUC ≥ "人数差+经济"启发式基线 +0.10） |
| 盲测 | 模型指出的"胜率大跌时刻"（= 该改的决策点），用户认同比例 ≥60% |
| 红线 | 未经证据校验的模型输出一律不进报告（架构锁延续） |

## 3. 阶段

### T0 数据与特征（复用第一期 M2a/M2b，2026-11-14 / 11-28）

- 特征层 = M2a 提取的 tick 级事实（人数差、经济、装备、站位、视角、接敌、存活）——**第一期本来就是地基，零重复劳动**。
- 样本 = 每回合采样 tick 的局面快照；标签 = 本回合最终胜负。
- **数据量微探针（2026-11-28 前）**：清点可用回合样本数（自己的 demo + 职业 demo 渠道【未知】待查证，含合规性）。<1000 回合 → 触发降级（§5）。

### T1 胜率模型 v0（2026-12-12）

- 模型：**GBDT（LightGBM）**——快、可解释、抗过拟合、MBP 上分钟级训练。
- 验收：AUC ≥ 基线 +0.10；训练/验证**按场次切分**防数据泄漏。

### T2 胜率模型 v1 + 集成（2027-01 考试周后）

- 升级：小 Transformer（百万级参数，序列局面）或保持 GBDT（看 v0 结果定）。
- 集成：tactics 层给可疑回合算"胜率掉点"→ 报告输出"这步决策让胜率从 X% 掉到 Y%"（带 tick 证据）；LLM 只解读这个数字。
- 验收：盲测认同率 ≥60%（§2）。
- 头 B（Rating+ 回归，2026-11-06 已通过）：`learn/rating_data.py` 场级聚合 → rating2，MAE 0.060 vs 均值基线 0.307，Spearman 0.963（valid n=46）。如实标注：adr/kd 占 gain 八成——学的是 5E 公式的权重（蒸馏），不是发现新规律；报告引用一律挂「按 5E 口径」。

### T3（可选，看 T2 再定）

- DPO 讲解风格支线（原 v1 主线）：仅当"说话方式"成为瓶颈时启动。
- 事件式理解（预测敌人下一步/下一个击杀方位）：T2 成功后再议。

## 4. 接口

- **对 PLAN.md**：M2a/M2b 产物（match.json / analysis.json 的 tick 事实）即训练特征源，第一期计划零改动。
- **对用户自建 train/ 文件**：建议 `train/data/`（特征+标签）、`train/models/`、`train/notebooks/`；特征 schema 以 `internal/model` 的 Match/Analysis 契约为唯一来源（`docs/CONTRACTS.md`）。
- **已落地（2026-11-01，复用 `learn/`，不新建 train/）**：
  - `learn/winrate_data.py`：T0 数据层，`match.json`（+ `analysis.json`）→ tick 快照，或回合级 `samples.jsonl`；
  - `learn/train_winrate.py`：T1 训练入口，LightGBM + 按 match 切分 + 「人数差+经济」基线 + AUC +0.10 验收 + `<1000 回合`降级标记；tick 快照才算 T1，回合级 `samples.jsonl` 仅作 v0 兼容、不算 T1；
  - `learn/configs/winrate.yaml`：超参与门槛；
  - `learn/train_winrate.py --drop-points`：T2 胜率掉点（带 tick 事件证据）输出；
  - `learn/train_winrate.py --score-drops`：T2 人工盲评认同率（≥60%、有效判定 ≥20）打分。
  - 训练默认会产出诊断模型；T1 硬性验收（AUC / 数据量 / valid 三项）用 `--strict`，不达标退出 2。

## 5. 时间预算与失败信号

| 阶段 | 用户投入 |
| --- | --- |
| T0 清点 | 每周 +10 分钟（随第一期顺带） |
| T1 | 1-2 个下午（GBDT 训练本身几分钟） |
| T2 | 2-4 小时（集成 + 盲测） |

kill criteria：

- 可用样本 **<1000 回合** → 胜率模型降级 GBDT 玩具版或暂缓，回退"规则 + LLM"形态。
- T1 AUC ≤ 基线 → 特征/数据不够，**停，不硬训**。
- 盲测认同 <60% → 模型输出不准进报告（防"假理解"进产品）。
- 主项目（PLAN.md 第一期）永远优先，训练线排 M2c 收口后；考试周停摆。

## 6. 风险

| 风险 | 可能性 | 影响 | 应对 |
| --- | --- | --- | --- |
| 数据量不足 | 高 | 高 | 微探针先行（11-28 出数）；职业 demo 渠道【未知】，查证后再用 |
| 过拟合（自己场次太少） | 高 | 高 | 按场次切分；GBDT 优先；必要时只训"丢分回合"子集 |
| "预测准" ≠ "讲得对" | 中 | 中 | LLM 解释层保留证据校验；只在掉点时刻输出建议 |
| Intel Mac | 低 | 中 | GBDT/小模型 CPU 也能训，不卡硬件 |
