# MAGLAB 磁轴工具箱 · CS2 辅助工具集

一个给 CS2 玩家（包括职业/半职业）用的**本机工具箱**：磁轴参数急停验证、鼠标传感器角度校准、电脑运算延迟优化。纯 HTML/CSS/JS + 一个可选的 Windows 桌面壳，无构建步骤、无第三方依赖、无网络请求，所有数据只保存在本机。

| 模块 | 入口 | 一句话 |
|---|---|---|
| 模块一 · 磁轴设置 / 急停实验室 | `index.html` | Source 物理重建速度曲线，量化急停动作 + A/B 磁轴参数 |
| 模块二 · 鼠标传感器旋转角度 | `sensor.html` | 水平滑动测轨迹偏移，给出鼠标驱动"传感器旋转"补偿角度 |
| 模块三 · 电脑运算延迟优化 | `optimizer.html` | 勾选生成优化脚本 + 回退脚本，降低 CS2 帧耗时 |
| 导航 | `tools.html` | 三个模块入口 + 配合流程 |

**建议流程**：先用「模块一」确定磁轴参数基准 → 用「模块二」校准传感器角度，保证水平/竖直滑动不偏移 → 用「模块三」优化系统，看 CS2 右上角帧数左侧的毫秒数是否下降。

**打开方式**：双击 `打开工具箱.bat`（或 `打开工具箱.vbs`）进导航页；各模块也可直接用 Chrome / Edge 打开对应 `html`。Windows 桌面版见 [main.py](#windows-桌面版可选)。

## 模块一 · 磁轴设置 / 急停实验室

一个给 CS2 玩家（包括职业/半职业）用的**受控急停测试工具**。

它不再只记录 A/D 的 keyup/keydown。它用 Source 移动物理重建速度曲线，要求你在目标出现后完成：

> 松开旧方向键 → 点按反方向键 → 在速度进入 34% 精度带时开枪

然后记录你的**开枪速度、停到精度带的时间、松键→反键间隔、反键按住时长、反向过冲、反应和一致性**。

> **边界**：这是受控物理模型，不是 CS2 游戏内遥测。它不读取游戏内存，也不替代 Counter-strafe Master / aim_botz 的实战复验。它的价值是：把"急停"拆成可重复、可量化、可 A/B 的动作数据。

## 快速开始

1. 用 **Chrome / Edge** 打开 `index.html`（或双击 `打开测试.bat`）。
2. 在「测试条件」里选择武器、次数、模式，填写配置标签。
3. 可选：展开「当前键盘设置与硬件画像」，填入当前触发行程、死区、RT 和误触画像；这会让报告里的参数建议更贴合你。
4. 建议先点「先练习 5 次」，熟悉"目标出现 → 松旧键 → 点反键 → 精度带内开枪"的节奏。
5. 开始正式测试：20 次（推荐）或 12 次（快速）。左右方向交替。
6. 基础块结束后，默认追加 **8 次比赛模拟**：目标出现后 900ms 内完成急停 + 开枪。只加时间压力，不加瞄准；可以跳过。
7. 看报告：核心指标、速度曲线、单组分布、**压力转移**、技术诊断、参数起点、A/B 对比。
8. 改一个键盘参数，再点「测试第二套配置」，用相同条件做 A/B；A/B 会包含同样的比赛模拟块。

所有数据只保存在本机浏览器 `localStorage`，不上传。右上角「清空」可重置。

### 测试前

- 关闭输入法。
- 使用平时打 CS 的坐姿、手位、鼠标和键盘。
- **先做键盘满程校准**：松开所有键 → 逐个按到底。
- 测试全程不要改键盘设置；A/B 时一次只改一个参数。
- 用 Chrome / Edge；手机可以打开页面，但测试需要实体键盘和鼠标。

## 测试协议

### 1. 按住方向键

每次开始会提示 `HOLD A` 或 `HOLD D`。按住该方向键，保持到目标出现。

- 测试会在你按住后等待 1.05–1.80 秒再给目标；这是为了让你达到该武器的最大速度。
- 目标出现前松开方向键、按下反键、或提前开枪，都会判为无效组并重试。

### 2. 松旧键 + 点按反键

目标出现后：

- 松开旧方向键（例如 A）
- 点按反方向键（例如 D）
- 不要用 Snap Tap / SOCD；本测试只模拟手动输入。CS2 官方服务器已禁止硬件辅助急停。

### 3. 在精度带内开枪

速度 ≤ 武器最大速度的 34% 时，用鼠标左键点击靶区。

- 34% 是社区常用的移动精度参考（Counter-strafe Master 使用同一口径）。
- 实际武器 inaccuracy 会随武器、距离和射击状态变化，所以报告同时给出**原始速度**，不只看"过/不过"。
- 完全停止（≤1 u/s）也会单独统计。

### 4. 无效组与重试

以下情况会标记为无效，不计入有效样本：

- 目标出现前松开旧键
- 目标出现前按下反键
- 目标出现前开枪
- 2.5 秒内没有检测到开枪

无效组会重试同一方向，有效样本达到设定次数才结束。

### 5. 测评模式 / 训练模式

- **测评 · 盲测**：不显示实时速度与速度曲线，避免盯着仪表盘调整按键；开枪后才显示这一组的数据。
- **训练 · 显示速度**：实时显示速度、精度带和速度曲线，用来建立节奏。训练数据同样按正式流程记录，但建议正式对比时用盲测。

### 6. 比赛模拟块（默认 8 次）

基础块结束后，工具会询问是否进入比赛模拟：

- 目标仍然居中，**不加瞄准**，只加时间压力。
- 目标出现后 **900ms** 内必须完成急停 + 开枪；超时记为一次失败。
- 记录：压力下的精度带命中率、中位停速、中位开枪速度、过冲率、窗口超时率。
- 报告会对比「基础块 vs 压力块」，判断你的动作是否能迁移到更接近比赛的节奏。
- A/B 会锁定同样的压力块设置，避免两套配置测的不是同一种环境。

> 没有真实比赛环境时，手感差异往往来自时间压力、决策和紧张度，而不是轴体本身。压力块就是把这个变量单独拿出来测。它仍然不是完整比赛：没有敌人瞄准、地图、经济和心理压力，所以最终还要游戏内复验。

### 7. 多时段复测

同一个人不同天的手感会变。建议：

- 第一次：基础 + 比赛模拟，建立基准。
- 改参数后：A/B 第二组。
- 隔 1–2 天：用同一配置再测一次，看压力块的波动。
- 报告里的前后段差异、压力块差异和 A/B 差异一起看，不要用单次"手感好"做决定。

## 物理模型

### 默认参数

| 参数 | 值 | 说明 |
| --- | --- | --- |
| `sv_accelerate` | 5.5 | 地面加速度 |
| `sv_friction` | 5.2 | 地面摩擦 |
| `sv_stopspeed` | 80 | 低速摩擦控制速度 |
| 物理步长 | 1 ms | 近似 CS2 sub-tick 的输入应用 |
| 精度带 | 34% of max speed | 社区移动精度参考 |

### 武器最大速度

| 武器 | 最大速度 |
| --- | --- |
| AK-47 | 215 u/s |
| M4A4 | 225 u/s |
| AWP | 200 u/s |
| SSG 08 | 230 u/s |

### 参考量级（AK-47，215 u/s）

- 1 ms 模型：立即反键，约 **75 ms** 进入 34% 精度带，约 **120 ms** 到零。
- 社区 64 tick 参考量级：约 **80 ms** 进入精度带，**110–125 ms** 完全停止。
- 这些是物理/社区参考，不是职业标准；你的实际值会受输入时序、键盘和样本影响。

### 模拟顺序

每一毫秒：

1. 应用地面摩擦（`max(speed, 80) * 5.2`）。
2. 按当前按键状态计算 wish direction。
3. 应用加速度（`5.5 * dt * maxSpeed`，以 `addSpeed` 封顶）。
4. 记录速度、精度带、零点、过冲和距离。

两键同时按住时，移动输入为 0，只剩摩擦；这和手动重叠输入的行为一致。模拟器不模拟 Snap Tap。

### 为什么不是直接读键盘模拟量

不同品牌磁轴的 HID 协议、RT 算法和驱动实现差异很大，通用读取并不可靠；而急停是否"适合你"，核心取决于**速度归零过程 + 开枪时机**，不是某一个模拟量数值。这个工具测的是键鼠输入经过你的键盘后，游戏实际会看到的行为时序。

### 模型不包含什么

- 服务器 64/128 tick 的离散化
- 网络延迟、丢包、peeker's advantage
- 武器实际 inaccuracy / 弹道 / 命中判定
- 鼠标瞄准误差
- 地图碰撞、斜坡、跳跃、蹲伏
- 你的键盘 RT 算法内部实现

所以最终必须用游戏内地图复验。

## 报告指标

| 指标 | 含义 | 越好 |
| --- | --- | --- |
| 精度带命中率 | 开枪时速度 ≤ 34% 的比例 | 越高越好 |
| 中位开枪速度 | 开枪时的速度中位数 | 越低越好 |
| 停到 34% | 从旧键松开到进入精度带的时间 | 越低越好 |
| 制动效率 | 理论最优停速 / 实际停速 | 越接近 100% 越好 |
| 松键→反键 | 旧键 keyup 到反键 keydown 的间隔 | 接近 0 最好；大正数=空档，负数=重叠 |
| 反键按住 | 反键 keydown→keyup 的时长 | 接近理论 tap 最好 |
| 过冲率 | 速度反向超过 10 u/s 的组比例 | 越低越好 |
| 提示→松键 | 目标出现到旧键松开的反应 | 越低越好 |
| 提示→开枪 | 目标出现到开枪的总时间 | 结合精度看 |
| 开枪速度波动 | 同一动作下开枪速度的 CV | 越低越稳 |
| 压力精度 | 比赛模拟块的精度带命中率 | 越高越好 |
| 窗口超时率 | 900ms 内没开枪的比例 | 越低越好 |
| 内部评分 | 基础块综合指标，见下 | 仅作内部参考 |

### 内部评分权重

| 维度 | 权重 |
| --- | --- |
| 精度带命中率 | 55% |
| 中位开枪速度 | 15% |
| 制动效率 | 15% |
| 过冲控制 | 10% |
| 开枪时机 | 5% |

评分是工具内部用于跟踪进步/ A/B 的指标，不是官方排名，也不代表职业水平。一个 100% 精度带、低过冲的 20 次样本，通常比单次"手感很好"更有参考价值。

## 怎么读报告

### 典型问题与含义

- **精度带命中率低**：开枪太早。先练"看到精度带再点击"，不要用更灵敏的 RT 掩盖。
- **停到 34% 慢，且松键→反键是大正数**：松键和反键之间有空档，反向加速开始得晚。
- **停到 34% 慢，且重叠率高**：旧键松得晚，双键按住期间只有摩擦，没有反向加速。
- **反键 tap 偏短**：速度还没降到精度带就松开了反键。
- **过冲率高**：反键按得太久，速度已经反向；先练在 0 点松键。
- **精度带命中但开枪偏晚**：停速不错，但决策/开枪慢；这不是键盘参数能解决的。
- **开枪速度波动大**：动作不稳定，先固定握姿、手位和 tap 时长，再做 A/B。

### 参数建议怎么用

报告给出的触发行程、顶部/底部死区、RT 按下/抬起、连续 RT 是**起点**，不是唯一答案。

- **松键/重叠问题** → 优先看 RT 抬起（更小的复位距离可以让旧键更早被读到）和触发行程。
- **反键空档/触发慢** → 优先看 RT 按下和触发行程（更小的按下距离让反键更早进入游戏）。
- **过冲** → 先练在 0 点松反键；RT 抬起可以更灵敏，但不要用它替代动作。
- **误触/手重** → 顶部死区加大；不要只靠降低触发行程。
- **底部死区** → 影响按到底的过冲和可用行程；不是急停的主要参数。

**参数只影响输入被游戏读到的时刻，不能修正松键、反键和开枪时机。** 如果诊断显示动作问题，先练动作。

**压力转移**：如果基础块精度带命中率正常，但比赛模拟块明显下降，说明你的动作在时间压力下不稳定。此时不要追求更激进的参数；先重复压力块，确认是紧张/决策问题还是键盘响应问题。如果压力下主要是"旧键松得晚/重叠"，再考虑 RT 抬起和触发行程；如果只是早枪，练开枪时机。

## A/B 测试：职业用法

这是本工具最重要的部分。不要相信一次公式输出，直接比较。

1. 完成一组 A（基准），建议 **20 次盲测**。
2. 看报告，只选一个与主要问题相关的参数（例如 RT 抬起）。
3. 回到键盘驱动，只改这个参数（0.01–0.05mm 或 0.05–0.1mm）。
4. 点「测试第二套配置」，配置标签写清楚（如 `RT 0.08`）。
5. 保持相同武器、次数、模式，完成 B。
6. 看 A/B 对比：精度带命中率、中位开枪速度、停到 34%、效率、重叠率、过冲率，以及压力精度/压力超时率（如果两边都测了比赛模拟）。
7. 至少重复 2 次 A/B，或交替 A/B，避免把疲劳/热身差异当成设置差异。
8. 如果基础块和压力块差异大，优先用**比赛模拟模式**的 A/B 结果，而不是基础块的漂亮数据。

**一次只改一个参数。** 同时改触发、死区和 RT，你无法知道是哪一项起作用。

## 模块二 · 鼠标传感器旋转角度检测

部分鼠标传感器存在安装角度偏差：明明是水平滑动，轨迹却斜着飘。这个模块测出偏移量，给出填进鼠标驱动的补偿角度。

1. 用 Chrome / Edge 打开 `sensor.html`（或从工具箱导航进入）。
2. 在平时用的鼠标垫上，沿页面提示**水平来回滑动 10 次以上**，轨迹会实时画在画布上。
3. 读取结果：轨迹偏向（左/右/上/下）+ **推荐驱动角度**。
4. 把该数值填入鼠标驱动的"传感器旋转 / 角度补偿"项。
5. 进 CS2 验证：十字线水平/竖直移动是否变直，以游戏内手感为准。

本工具仅在本机浏览器运行，不上传任何数据。Windows 桌面版（`main.py`）内置了同一检测。

## 模块三 · CS2 电脑运算延迟优化

目标：降低 CS2 右上角帧数左侧的毫秒数（电脑运算延迟）。页面本身**不改系统**——你勾选项目后生成优化脚本（`.bat`）+ 回退脚本，自己右键"以管理员身份运行"才生效；改前自动提示备份，一键还原。`检查优化状态.bat` 可复查当前状态。

| 类别 | 优化项目 |
|---|---|
| 通用 | 电源计划 → 高性能 / 终极性能；Windows 游戏模式开；硬件加速 GPU 调度开；CS2 启动参数；cs2.exe 进程优先级 → 高；清理系统临时文件 |
| 笔记本专用 | 独显直连 / 强制独显输出；插电时最小处理器状态 100%；禁用 USB 选择性暂停；禁用 PCIe 链路状态电源管理；关闭 Windows 快速启动；禁用 SysMain；禁用 Windows 搜索索引 |

优化完进 CS2，看右上角帧数左侧毫秒数是否下降。Windows 桌面版（`main.py`）同样可以生成脚本。

> 风险提示：优化脚本会改电源计划、系统服务与注册表相关项。执行前确认已备份（脚本自带回退），笔记本注意散热；任何一项导致异常，用回退脚本还原即可。

## 常见问题

**Q：这是游戏内测试吗？**
A：不是。它是受控物理模拟 + 真实键鼠输入。最终用 Counter-strafe Master / aim_botz 复验。

**Q：为什么不用读轴仪/模拟量？**
A：不同品牌协议不同，且急停的核心是速度曲线和开枪时机。本工具用键鼠事件重建游戏看到的行为；A/B 时比较的是实际输入时序。

**Q：为什么我的停速和理论差很多？**
A：先看松键→反键间隔、重叠、tap 时长、过冲。大多数损失来自动作，不是轴体。报告会指出主要损失。

**Q：34% 是绝对准确线吗？**
A：不是。它是社区常用参考，实际武器 inaccuracy 会随距离/状态变化。报告同时给出原始速度；不要只看"过/不过"。

**Q：为什么后坐/弹道没有模拟？**
A：这个工具只测急停，不测压枪/弹道。用 Recoil Master / 游戏内训练。

**Q：为什么我在练习/死斗里很准，比赛里手感不一样？**
A：常见原因是时间压力、决策、紧张度和热身状态，不是轴体突然变了。工具现在有 900ms 比赛模拟块，用来测同一套动作在时间压力下是否稳定；如果压力块明显下降，优先用压力模式做 A/B，并在不同天重复基准，不要用单次练习数据定参数。

**Q：手抖/误触多，参数怎么选？**
A：提高顶部死区、保守 RT 抬起；先做基础版静置/悬停测试补充画像。

**Q：传感器角度测出来了，但游戏里还是斜？**
A：先确认驱动里的补偿角度已保存并重启游戏；部分鼠标驱动的角度项是"旋转"而不是"补偿"，符号可能要取反。最终以 CS2 里十字线直线度为准。

**Q：优化脚本安全吗？**
A：脚本内容就是页面勾选的项目，执行前可以打开 `.bat` 逐行看；自带回退脚本，出问题一键还原。不要运行来历不明的版本，只用本仓库生成的。

**Q：能用在其他游戏吗？**
A：物理参数是为 CS2/Source 调的；其他游戏需要改模型，不建议直接套用。
